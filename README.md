# 好好吃飯｜一週菜單與採買

以繁體中文安排一週菜單，並自動整理採買清單的靜態網頁工具。支援桌面與手機；食譜配餐在瀏覽器執行，共用資料透過 Firebase Authentication 與 Cloud Firestore 同步。

## 功能

- 27 道內建食譜，顯示份量、預估備餐時間、設備與簡單步驟。
- 預設規劃七天午餐與晚餐；平日與週末可使用不同用餐人數。
- 依忌口、偏好、備餐時間和每週主食餐數安排菜單。新預設為午餐＋晚餐、每餐最多60分鐘、義式與西式；亦可選美式。
- 預設忌口為青椒、茄子、酪梨、照燒、番茄、豬肉、雞肉調理包。輸入內容立即自動保存，產生菜單後套用。
- 設定草稿、既有菜單與冰箱資料分開保存；未按產生或尚未加入的冰箱輸入也可在重載後恢復。
- 家中設備為 BOSCH PXY875KW1E Flex IH、氣炸鍋、電子鍋、BOSCH BEL554MS0U 微波燒烤爐、BOSCH HSG7584B1 蒸烤爐；食譜會對應設備名稱與機型。
- 換菜選單列出所有符合條件的同類料理，可搜尋食材、設備或料理名稱，亦可依主要蛋白質篩選。
- 可任意多次指定換菜；自動挑選先輪過候選再重複，並遵循目前篩選。其餘餐點維持不變，採買清單同步重算。
- 每餐可勾選「已煮好」，採買只計算未煮餐點；取消標記會加回，狀態隨菜單保存。
- 合併同種食材、依人數換算份量，從未煮餐點需求扣除目前庫存。標記已煮好不會自動修改庫存，請填寫實際現有量。
- 分類採買、逐項勾選、複製與列印清單。
- 記錄喜好、備餐耗時與份量回饋。
- JSON 備份匯出與匯入。

## 家人使用與資料保存

GitHub Pages 前端網址維持不變。完成 Firebase 設定後，家庭管理者與指定的一位家人各自使用 Google 帳號登入，即可共用最新菜單、有效設定、庫存、已煮標記、採買勾選與料理回饋。Firebase 主控台權限只需管理者持有。

首次建立共用餐桌必須由管理者明確選擇此裝置的資料，不會自動把預設菜單上傳或覆蓋既有雲端資料。未登入時繼續使用原有的瀏覽器個人資料；登入後的雲端資料與個人資料分開，登出會恢復個人資料。

有效的偏好欄位會在停止輸入約700毫秒後同步，產生菜單後才套用到本週。未完成或無效的數字、尚未加入的冰箱輸入保留在目前帳號的此裝置草稿。只有收到伺服器確認才顯示「已同步」；送出後若因斷線無法確認結果，會保留同一操作識別碼，確認後才開放下一次操作，避免庫存重複增加；離線時可查看已載入內容，恢復連線後再修改，不會將離線操作排入背景佇列。

不同餐點、不同偏好欄位可以合併；同一道菜或同一偏好欄位有衝突時會提示重新確認，避免無聲覆蓋。庫存新增依食材合併加總，移除則檢查原數量；採買勾選會檢查週次和最新需求量。重產生菜單與匯入備份會檢查原菜單版本。

目前 `firebase-config.js` 為 `null`，尚未連接正式 Firebase 專案。此狀態只啟用個人瀏覽器模式，登入按鈕停用，畫面清楚顯示雲端未開通。正式啟用步驟見 [FIREBASE_SETUP.md](FIREBASE_SETUP.md)。

此版本使用內建食譜庫依條件配餐，不會即時呼叫 AI API。份量與時間為食譜估算；喜好與耗時會影響後續配餐排序，份量回饋留作自行調整參考。

## GitHub Pages 部署

所有網站檔案都位於儲存庫根目錄，使用相對路徑，可部署於 GitHub Pages 專案網址。

1. 將檔案推送至 `main` 分支。
2. 在儲存庫的 **Settings → Pages** 選擇 **Deploy from a branch**。
3. 分支選擇 **main**，資料夾選擇 **/ (root)**，儲存後等待發布完成。

`.nojekyll` 讓 GitHub Pages 直接提供靜態檔案，不經 Jekyll 處理。

## 開發與測試

使用純 HTML、CSS 與 JavaScript ES modules，無需安裝依賴或執行建置。透過任意靜態伺服器提供根目錄即可預覽。

```sh
npm test
node --check app.js
node --check engine.js
```

核心測試涵蓋七天／十四餐規劃、平假日份量、週三換菜後採買重算、庫存合併與單次扣抵、忌口與備餐時間、無解條件、小數精度、日期跨月跨年與輸入不可變性。

## 檔案

- `index.html`：頁面結構與操作表單。
- `styles.css`：響應式樣式。
- `app.js`：介面互動、個人資料保存與備份。
- `cloud-ui.js`：共用狀態、帳號隔離、草稿與介面狀態。
- `firebase-sync.js`：Google 登入、家庭成員、即時監聽與交易傳輸。
- `sync-model.js`：逐餐／逐欄位合併、衝突檢查及庫存與勾選保護。
- `firestore.rules`：家庭成員權限與資料版本規則。
- `engine.js`：食譜資料、菜單產生與採買計算。
- `tests/engine.test.mjs`：核心邏輯測試。
- `tests/defaults.test.mjs`、`tests/preferences.test.mjs`：新預設、草稿、庫存與遷移測試。

一般測試執行 `npm test`。另有 `tests/firestore-rules.emulator.mjs` 使用官方 Firestore Emulator 進行真實權限與雙帳號整合測試，執行方式見 Firebase 設定文件。
